# Glossarizer

Client-side glossary for LibreTexts pages. It loads glossary terms from the Commons API, renders a glossary list, and wraps matching terms in page content with accessible tooltips.

## Features

- Fetches glossary data by page ID and library, with localStorage caching (1 hour TTL)
- Renders an alphabetical glossary list into `#glossary-output`
- Glossarizes terms inside `.mt-content-container` (and its children)
- Interactive Tippy tooltips with definition, attribution, and media tabs
- MathJax support in glossary list and tooltips (including mhchem)
- Skips matches inside LaTeX, MathJax output, code/pre, scripts, and the glossary list itself
- Term aliases; longest-match-first so multi-word terms win over substrings
- Click a glossary term to scroll to its first in-page occurrence
- Image lightbox with keyboard focus trap
- Keyboard-accessible tabs and tooltips
- _(TypeScript build only, `src/`)_ Watches the content root for nodes added after the initial pass (lazy-loaded sections, late-rendering widgets) and glossarizes just the new content — the legacy `script.js`/`glossarizer.js` only glossarize once and miss anything added afterward

## Files

| File | Purpose |
|------|---------|
| `script.js` | Legacy hand-written source: API fetch, cache, glossary list render, MathJax config |
| `glossarizer.js` | Legacy hand-written source: in-page term matching, Tippy tooltips, lightbox |
| `script.min.js` / `glossarizer.min.js` | Legacy minified production builds |
| `src/` | TypeScript rewrite of the same functionality (see below) — the maintained source going forward |
| `dist/glossarizer.js` / `dist/glossarizer.min.js` | Built output of `src/`, generated by `npm run build` |
| `LICENSE` | MIT |

The legacy `script.js`/`glossarizer.js` files are kept as-is for any page still
loading them directly. New work happens in `src/`; `dist/glossarizer.js` (or
its minified twin) is a drop-in replacement — swap it in with a single
`<script>` tag in place of the old two-script pair.

## Required DOM

Pages need these elements for the scripts to run:

```html
<input type="hidden" id="pageId" value="6543" />
<input type="hidden" id="coverID" />
<div class="mt-content-container"><!-- page prose --></div>
<div id="glossary-output"></div>
```

Load order (source or minified):

```html
<script src="script.js"></script>
<script src="glossarizer.js"></script>
```

MathJax should be available on the page (LibreTexts loads it, or include it yourself). Tippy/Popper are loaded from CDN by `glossarizer.js` if missing.

## API

Base host defaults to `https://commons.libretexts.org` (override `API_HOST` in `script.js` for local development).

| Method | Endpoint | Use |
|--------|----------|-----|
| `GET` | `/api/v1/commons/glossary/page/{pageId}/library/{library}` | Freshness check; returns `coverID` and `latestUpdatedAt` |
| `POST` | same path | Full glossary payload (`items`, `coverID`, `library`, …) |

Library is derived from the hostname subdomain (e.g. `chem.libretexts.org` → `chem`; localhost → `dev`).

Cache key: `glossary-data-{coverID}-{library}`.

## Build (TypeScript source, `src/`)

The maintained source lives in `src/` as TypeScript, structured by feature:

```
src/
  config.ts                  API_HOST, license map, cache TTL
  types.ts                   GlossaryItem/GlossaryData/API response types
  global.d.ts                window.MathJax + window._gt* ambient declarations
  utils/                     library/anchor/latex/html/cache helpers
  mathjax/                   pre-load config + typeset helpers
  tooltip/                   tooltip HTML template, tabs, lightbox, Tippy wiring, styles
  features/glossaryTable/    fetch + render the glossary list (was script.js)
  features/glossarize/       in-page term wrapping + tooltip attach (was glossarizer.js)
  index.ts                   composition root
```

Install dependencies and build with pnpm (or npm):

```bash
pnpm install
pnpm run build       # -> dist/glossarizer.js, dist/glossarizer.min.js
pnpm run dev         # incremental rebuild on change
pnpm run typecheck   # tsc --noEmit
```

`dist/glossarizer.js` bundles everything — including Tippy.js, which is now
an npm dependency instead of being injected from a CDN at runtime — into one
`<script>`-tag-ready file:

```html
<script src="dist/glossarizer.js"></script>
```

`API_HOST` is baked into the bundle at build time from the `API_HOST`
environment variable (see `.env.example`); copy it to `.env` and point it at
a local API server for development. `dist/` and `node_modules/` are
build output and are not committed (see `.gitignore`).

`index.html` and `version.txt` are local-only (listed in `.gitignore`).
